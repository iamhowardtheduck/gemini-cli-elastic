Throughput levers · the same as for Claude Code

Six settings decide the ML bill. The zero-shot passes come first.

Gemini CLI uses the same models and the same 11 ML calls per classified prompt, so the levers are the ones from the Claude Code tests. Lever 04 comes from the earlier tuning measurements in docs/inference-tuning.md.

01 · Allocations

Fixed zero-shot allocations, sized up front

Set number_of_allocations for the zero-shot model from your peak and provision the ML capacity to hold it.

82.7% of classifier time
02 · Passes

Run fewer zero-shot passes

Cost scales with passes and labels per pass. Security and agent action alone need 2 of the 5 passes.

2 of 5 passes
03 · Scope

Classify by policy, embed everywhere

Inference is a per-policy switch. Classify the teams that need it; everyone else gets embeddings and semantic threat flags.

ML cost ∝ classified share
04 · Threads

One thread per allocation

Ingest-time inference is many small requests. One thread each gave about 2× the work per core of 8-thread allocations.

≈2× per vCPU
05 · Agent output

Small bulk requests

Classified bulks took 25 to 41 s here, and reached the 120 s client timeout once saturated. bulk_max_size: 200 keeps each request short.

200 events per request
06 · Backfill

Backfill without classification

A new agent reads up to 30 days of Gemini CLI chats at once. Turn classification off for the backfill, then back on for live prompts.

history embedded, not classified
