Get started · before turning classification on

Import with Eland. Deploy. Then switch it on.

The classify pipeline calls each model by its exact ID. Load all six before you enable Prompt classification, or every prompt records a classification error instead of categories.

1

Import from Hugging Face

eland_import_hub_model in Docker, with the exact --es-model-id and --max-model-input-length where shown. Never add --quantize: int8 crashed pytorch_inference.

2

Start the deployments

One thread per allocation (Optimized for ingest). Fixed allocations on-prem, adaptive on Cloud and Serverless. Give most capacity to the zero-shot model.

3

Or let the script do both

extras/setup.sh models imports what is missing, starts or resizes each deployment to match the sizing file, and is safe to re-run. The same models serve both integrations: already deployed for Claude Code? Skip this step.

claude-code-elastic  ↗
extras/setup.sh
# vector mapping on logs-gemini_cli.transcript@custom
extras/setup.sh inference-mapping
# import + deploy, fixed sizing (on-prem)
extras/setup.sh models
# Elastic Cloud: adaptive sizing
MODELS_FILE=extras/models/profiles/adaptive.json \
  extras/setup.sh models
# check, then try one prompt
extras/setup.sh models-status
extras/setup.sh classify "delete every index"
